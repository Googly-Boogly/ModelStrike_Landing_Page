# ModelStrike website

Marketing site for ModelStrike (AI agent security assessments / red teaming). Next.js 16 App Router, React 19.2, TypeScript strict, Tailwind CSS 4. The only runtime dependencies are `next`, `react` and `react-dom` — don't add packages (validation libs, UI kits, icon sets, analytics SDKs) without asking. README.md has the full setup, Docker and deployment notes.

## Commands

```bash
npm run dev         # http://localhost:3000 (Turbopack; reads .env.local)
npm run lint        # eslint directly — `next lint` no longer exists in Next 16
npm run typecheck   # next typegen && tsc --noEmit
npm run check       # lint + typecheck + build — run this before calling work done
```

There is no test suite. `main.py` and `.venv/` are PyCharm scaffolding, unrelated to the site — ignore them.

## Next.js 16 specifics that matter here

Check `node_modules/next/dist/docs/` before using any Next API from memory (the upgrade notes are in `01-app/02-guides/upgrading/version-16.md`). Things this codebase relies on:

- Request APIs are async only: `await headers()`, `await cookies()`, `await params`. Sync access is removed.
- `PageProps<"/route">` / `LayoutProps<"/route">` are global types generated by `next typegen` (see `src/app/layout.tsx`). If they're missing, run `npm run typecheck`, not a manual type.
- `await connection()` from `next/server` opts a page into per-request rendering (used by `/contact`).
- Middleware is now `proxy.ts` with a `proxy` export, if one is ever needed.
- `next build` doesn't lint; the ESLint flat config lives in `eslint.config.mjs`.

## Architecture

- **Copy lives in `src/content/`** (`site.ts`, `home.ts`, `services.ts`, `about.ts`) as typed data. Components render it; don't hard-code marketing copy in components.
- **`src/content/site.ts` is the only place that reads `NEXT_PUBLIC_*` env vars.** Empty values must hide the UI element or fall back safely (e.g. `bookingHref` falls back to `/contact`, `socialLinks` filters out blanks, `security.txt` 404s without a security email).
- **Pages are static by default.** Exceptions: `/contact` (`connection()`, so the "not connected" banner reflects runtime env) and `security.txt/route.ts` (`force-dynamic`, so `Expires` stays fresh). Anything time- or env-dependent at runtime needs the same treatment — or, like `CurrentYear`, render on the client.
- **Client JS is kept minimal.** Only `MobileNav`, `ContactForm`, `CalEmbed` and `CurrentYear` are `"use client"`. Keep new components as Server Components unless they need interactivity.
- **Page metadata:** use `pageMetadata({ title, description, path })` from `src/lib/metadata.ts` in each page; add new routes to `src/app/sitemap.ts` and, if navigable, `primaryNav` / `footerNav` in `site.ts`.
- **UI primitives** in `src/components/ui/`: `Section`/`Container` for page sections, `ButtonLink`/`buttonClasses` for buttons (external URLs automatically open in a new tab), `SectionHeader`, `CheckList`. Reuse them.
- Path alias: `@/*` → `src/*`.

## Contact form (security-sensitive)

Flow: `ContactForm` (client) → `submitContact` Server Action (`src/app/contact/actions.ts`) → `validateContact` (`src/lib/contact/schema.ts`) → `resolveDelivery()` (`src/lib/contact/delivery.ts`).

- The server is the source of truth for validation. `schema.ts` is shared with the client only for option lists and `limits`. Any new field needs: type in `ContactSubmission`, a limit, server validation, the form field, and inclusion in `formatPlainText`.
- Anti-spam order in the action: honeypot (`website`, returns fake success) → minimum fill time (`elapsedMs` ≥ 3s) → per-IP in-memory rate limit → validation. Keep it.
- Never render submitted content as HTML, and never log visitor personal data (errors log only the provider name and message).
- Server-only modules (`delivery.ts`, `rate-limit.ts`, `team-photo.ts`) import `"server-only"`; keep secrets out of anything a client component imports.
- New delivery provider: implement `ContactDelivery` and add a case in `resolveDelivery()`; return `null` when its env vars are incomplete.

## Security headers / config

`next.config.ts` sets a nonce-less CSP (so pages stay static), HSTS, frame denial, etc. for every route. Don't loosen the defaults — third-party origins go in `CSP_SCRIPT_SRC` / `CSP_CONNECT_SRC` / `CSP_FRAME_SRC`. Image optimization is limited to `/team/**` via `images.localPatterns`; widen it deliberately if other images need `next/image`. `output: "standalone"` is required by the Dockerfile.

Env var split: `NEXT_PUBLIC_*` and `CSP_*` are baked in at build time (Docker build args); `CONTACT_*` / `RESEND_API_KEY` are runtime-only secrets. Never put a secret in a `NEXT_PUBLIC_*` var. When adding a build-time var, update `.env.example`, `Dockerfile` (ARG + ENV) and `compose.yaml` build args together.

## Styling

Tailwind 4 with tokens defined in `@theme` in `src/app/globals.css` — no `tailwind.config`. The site is dark-only by design. Use the existing tokens (`ink-*` backgrounds, `line`/`line-strong` borders, `fg`/`fg-muted`/`fg-subtle` text, `strike-*` accent; `strike-400` for accent text on dark, `strike-600` behind white text) rather than raw colors; the pairs are chosen for WCAG AA contrast. Animations must respect `prefers-reduced-motion` (handled globally). Preserve accessibility patterns already in use: skip link, `aria-labelledby` on sections, `aria-invalid`/`aria-describedby` on form fields, focus management after form submission.

## Team photos

`findTeamPhoto(slug)` looks for `public/team/<slug>.{jpg,jpeg,png,webp}` at build time and falls back to an initials avatar. Restart dev / rebuild after adding one.
